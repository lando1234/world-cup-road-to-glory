Core Assumptions

  • A1 · Knockout is linear, not map 8

    Football knockout uses eliteIndex gate chain + knockout_teams.json. Legacy startMap(8) + generateMap() is Pokemon Elite Four only.

  • A2 · knockoutEnabled gate is singular

    Only task P5-017 may flip FEATURES.knockoutEnabled to true, after data + runner + trophy path validate.

  • A3 · Slice complete when knockout off

    Stamp 8 with knockoutEnabled: false must still route to Slice Complete → settleRunLite for regression.

  • A4 · Meta via domain/meta.js

    Settlement logic lives in pure functions per 008-meta-progression.md §18; UI never writes credits directly.

  • A5 · Catalog stand-ins acceptable

    Knockout rosters may use catalog stand-ins per 007-football-data-pack.md §8; full 50-player catalog not required for Phase 5 cut line.

  • A6 · One task, one commit

    Never mix knockout enable, economy, save migration, and content authoring in one commit.

Tradeoffs

  • Reuse elite-prep-screen vs new knockout UI

    Reskin existing prep screen for speed. Cost: temporary bridge DOM ids (elite-prep-*) until Phase 6 rename.

  • v3 flat keys before v4 blob

    Ship meta on additional localStorage keys without schema bump. Cost: more keys until Wave 6 consolidation.

  • settleRunLite regression path

    Keep lite settlement when knockout off. Cost: two settlement code paths until football always uses full meta.

  • Fixed historical bracket

    Seeded presentation only; gate order static per 007. Dynamic bracket seeding deferred Phase 6.

  • Legend recruit defer

    P5-053 may limit to album + trophy room display. Full legend recruit pool deferred if schedule tight.
